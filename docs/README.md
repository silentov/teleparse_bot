# Документация проекта

Этот каталог содержит актуальную проектную документацию, сверенную с кодом и runtime-конфигурацией на момент аудита.

## С чего читать новому разработчику

1. `onboarding.md` — чтобы поднять проект локально;
2. `architecture.md` — чтобы понять роли компонентов и границы ответственности;
3. `configuration.md` — чтобы разобраться с переменными окружения и режимами запуска;
4. `runtime.md` — чтобы понять жизненный цикл приложения и поведение во время работы;
5. `summarization-pipeline.md` — чтобы понять, как именно формируется сводка;
6. `troubleshooting.md` — чтобы быстро диагностировать типовые проблемы;
7. `development.md` — чтобы вносить изменения без нарушения текущей архитектуры.

## Что важно помнить

- Документация ниже опирается на **реальный код**, а не на исторические заметки.
- Если код и документация расходятся, source of truth — код и конфиги.
- Для сторонних библиотек в неочевидных местах проверялись официальные сведения через Context7.

## Старые документы в корне репозитория

- `DOCKER_GUIDE.md` — больше не является основной инструкцией по запуску;
- `IMPROVEMENTS.md` — архивный отчёт, полезен как исторический контекст, но не как описание текущего состояния.
