# Onboarding: как запустить проект локально

## 1. Что нужно понять до первого запуска

Проект — это не просто Telegram-бот по токену. Для работы ему нужны:

1. **ботовая сессия** Telegram для общения с пользователем;
2. **пользовательская сессия** Telegram для чтения истории каналов;
3. Redis для FSM и локов;
4. LLM API-ключ и system prompt для генерации сводки.

То есть локальный запуск — это комбинация Telethon + Redis + LLM-конфигурации.

## 2. Предварительные требования

Подготовьте:

- Python **3.13**;
- `uv` для установки зависимостей;
- Docker Desktop или локальный Redis;
- Telegram `api_id` и `api_hash` с `my.telegram.org`;
- токен бота от `@BotFather`;
- Telegram-аккаунт для userbot-сессии;
- ключ LLM-провайдера, совместимого с текущей конфигурацией `LangChain + DeepSeek`.

## 3. Рекомендуемый локальный сценарий

Наиболее реалистичный сценарий разработки сейчас:

- Redis запускать отдельно;
- само приложение запускать локально из корня репозитория;
- userbot авторизовать в интерактивном терминале один раз.

Именно этот путь лучше всего согласован с текущим кодом.

## 4. Подготовка конфигурации

### 4.1. Где должен лежать `.env`

В режиме `APP_ENV=local` приложение **жёстко ожидает** файл:

```text
src/.secrets/.env
```

Если файла нет, `get_settings()` завершит запуск с `ConfigurationError`.

### 4.2. Минимальный пример `src/.secrets/.env`

```dotenv
APP__API_ID=12345678
APP__API_HASH=your_telegram_api_hash
APP__TOKEN=123456789:telegram_bot_token

REDIS__HOST=localhost
REDIS__PORT=6379
REDIS__DB=0
REDIS__USERNAME=fsm
REDIS__PASSWORD=FsmPass8989

LLM__API_KEY=your_llm_api_key
LLM__MODEL=deepseek-chat
LLM__TEMPERATURE=0.3
LLM__TIMEOUT=30
LLM__TOKENS=8000
LLM__MAX_RETRIES=0
LLM__SYSTEM_PROMPT=Ты аналитик. Сформируй краткую сводку по сообщениям канала.
```

### 4.3. Что обязательно заполнить

Критично для старта:

- `APP__API_ID`
- `APP__API_HASH`
- `APP__TOKEN`
- `LLM__API_KEY`
- `LLM__MODEL`
- `LLM__SYSTEM_PROMPT`

Для Redis в типовом локальном сценарии практически также нужны:

- `REDIS__HOST`
- `REDIS__PORT`
- `REDIS__PASSWORD` — если используете `redis.conf` из репозитория

## 5. Поднимите Redis

### Вариант A. Через Docker Compose

Для локальной разработки удобнее всего поднять только Redis:

```bash
docker compose up -d cache
```

Что это даст:

- контейнер `redis:7.4-alpine`;
- конфиг из `redis.conf`;
- ACL-пользователя `fsm`;
- открытый порт `6379` на localhost.

### Вариант B. Собственный локальный Redis

Если Redis уже установлен локально, просто убедитесь, что:

- хост и порт совпадают с `REDIS__HOST` / `REDIS__PORT`;
- база данных доступна;
- аутентификация соответствует вашим настройкам.

## 6. Установите зависимости

Из корня репозитория:

```bash
uv sync
```

Проект использует lock-файл `uv.lock`, поэтому локальная установка ожидается именно через `uv`.

## 7. Запустите приложение

```bash
uv run python src/main.py
```

Запускать лучше **из корня репозитория**, а не из `src/`, чтобы поведение относительно session-файлов было предсказуемым.

## 8. Что произойдёт на первом старте

### 8.1. Bot API клиент

Ботовая сессия стартует через:

```python
await self._client.start(bot_token=self.__token)
```

Как правило, интерактивная авторизация тут не нужна — достаточно валидного bot token.

### 8.2. UserBot клиент

Пользовательская сессия стартует через:

```python
await self._client.start()
```

Если session-файла ещё нет, Telethon обычно попросит:

- номер телефона;
- код подтверждения;
- иногда пароль 2FA.

Это означает, что **первый запуск userbot должен происходить в интерактивном терминале**.

## 9. Где хранятся session-файлы

Имена сессий в коде зашиты так:

- `bot_session`
- `async_session`

Telethon сохранит их относительно текущей рабочей директории процесса. Если вы запускаете проект командой из корня репозитория, ожидайте файлы рядом с ним:

- `bot_session.session`
- `async_session.session`

Эти файлы содержат чувствительные данные и уже исключены из Git через `*.session`.

## 10. Быстрая проверка функциональности

После старта:

1. откройте диалог с ботом;
2. отправьте `/start`;
3. нажмите `📥 Получить посты`;
4. введите username публичного канала без `https://t.me/`;
5. выберите лимит или введите свой;
6. дождитесь ответа со сводкой.

## 11. Где смотреть логи

Приложение пишет:

- в консоль;
- в `src/logs/app.log`;
- в `src/logs/error.log`.

JSON-логгер в коде предусмотрен, но в `main.py` сейчас запускается с `log_json=False`.

## 12. Что важно не перепутать

- корневой `.env`, на который ссылается `docker-compose.yaml`, **не заменяет** `src/.secrets/.env` для локального режима приложения;
- Docker Compose в текущем состоянии лучше использовать как способ поднять Redis, а не как гарантированно рабочий полный runtime для всего приложения;
- если нужно дорабатывать production-запуск — сначала прочитайте `docs/configuration.md`.
