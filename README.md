# Документация проекта py_teleparse

## Общее описание

Проект py_teleparse представляет собой Telegram-бота с функциональностью парсинга публичных каналов. Он состоит из двух основных компонентов:
- **Bot API** - основной бот для взаимодействия с пользователями
- **UserBot** - клиент для парсинга каналов и получения сообщений

Проект использует Redis для хранения состояний диалогов (FSM) и распределенных блокировок для обеспечения корректной работы в многопоточной среде.

## UX (User Experience)

### Основной сценарий использования

1. Пользователь запускает бота командой `/start`
2. Бот отображает главное меню с кнопками:
   - "📥 Получить посты" - начало процесса парсинга
   - "ℹ️ Помощь" - информация о функциональности
3. При выборе "📥 Получить посты":
   - Бот запрашивает имя канала (формат: имя после t.me/)
   - После ввода имени канала бот предлагает выбрать количество постов:
     - Предустановленные значения: 10, 50, 100
     - "📝 Своё значение" - возможность ввести произвольное число
     - "❌ Отмена" - отмена операции
4. После выбора количества постов бот начинает парсинг и отображает результат
5. По завершении операции доступны кнопки:
   - "📥 Ещё запрос" - повторный парсинг
   - "🏠 В главное меню" - возврат в главное меню

### Особенности интерфейса

- Все взаимодействие происходит через inline-кнопки
- Состояния пользователя сохраняются в Redis с TTL 30 минут
- Используются распределенные блокировки для предотвращения race conditions
- При возникновении ошибок отображаются понятные сообщения об ошибках

## Внутреннее взаимодействие компонентов

### Архитектура проекта

src/

### Основные компоненты

#### 1. MainBot (bot_client.py)
Основной класс бота, который объединяет все компоненты:
- Обрабатывает входящие сообщения и callback-запросы
- Управляет состояниями пользователей через FSM
- Взаимодействует с UserBot для получения сообщений
- Отправляет ответы пользователям

#### 2. UserBot (userbot_client.py)
Клиент для парсинга сообщений из Telegram-каналов:
- Поддерживает постоянное соединение с Telegram
- Предоставляет метод `get_messages()` для получения сообщений
- Управляет жизненным циклом подключения

#### 3. RedisFSM (redis_fsm/)
Модуль управления состояниями пользователей:

##### RedisFSM (redis_fsm_impl.py)
- Управляет состояниями диалогов пользователей
- Сохраняет данные пользователей в Redis
- Предоставляет распределенные блокировки для сериализации операций

##### RedisFSMDispatcher (redis_fsm_dispatcher_impl.py)
- Распределяет входящие события по соответствующим обработчикам
- Поддерживает регистрацию обработчиков для различных состояний
- Обеспечивает сериализацию доступа к состояниям пользователей

##### FSMState (fsm_states.py)
Перечисление возможных состояний:
- `DEFAULT` - состояние по умолчанию
- `WAIT_CHANNEL` - ожидание имени канала
- `WAIT_LIMIT` - ожидание выбора количества постов
- `WAIT_CUSTOM_LIMIT` - ожидание ввода произвольного количества постов

#### 4. Keyboards (keyboards.py)
Модуль inline-клавиатур:
- `main_menu()` - главное меню
- `limit_picker()` - выбор количества постов
- `cancel_button()` - кнопка отмены
- `back_to_menu()` - возврат в главное меню
- `action_buttons()` - кнопки после успешного парсинга

#### 5. Config (config.py)
Модуль конфигурации:
- Поддерживает различные окружения (LOCAL, PROD)
- Управляет секретами через .env файлы и Docker Secrets
- Валидирует параметры конфигурации

### Поток данных

1. **Запуск приложения** (main.py):
   - Инициализация RedisManager
   - Создание RedisService и LockService
   - Инициализация Telegram-клиентов (Bot и UserBot)
   - Создание FSM и Dispatcher
   - Запуск MainBot

2. **Обработка сообщений**:
   - Входящее сообщение → MainBot.on_message()
   - Dispatcher определяет состояние пользователя
   - Вызов соответствующего обработчика
   - Обновление состояния через RedisFSM
   - Отправка ответа пользователю

3. **Парсинг каналов**:
   - Пользователь указывает имя канала и количество постов
   - MainBot вызывает UserBot.get_messages()
   - Результат отображается пользователю

## Инфраструктурные части

### Redis Module

Модуль Redis предоставляет комплексную интеграцию Redis для приложения, реализуя управление подключениями, соглашения об именовании ключей, распределенные блокировки и высокоуровневые операции Redis.

#### Компоненты Redis Module

##### 1. RedisManager (manager.py)
Управляет жизненным циклом подключения Redis:
- Инициализирует пул подключений
- Проверяет соединение при запуске
- Закрывает соединения при остановке

##### 2. RedisService (service.py)
Высокоуровневые операции с Redis:
- Работа с простыми значениями (get, set, delete)
- Работа с JSON-данными (get_json, set_json)
- Специализированные методы для профилей пользователей
- Методы для работы с контекстами FSM

##### 3. RedisKeys (keys.py)
Соглашения об именовании ключей:
- Единый префикс для всех ключей приложения
- Структурированные имена для различных типов данных
- Методы для генерации ключей блокировок

##### 4. LockService (lock_service.py)
Фабрика распределенных блокировок:
- Создание блокировок по различным критериям
- Специализированные методы для блокировок FSM
- Методы для блокировок ресурсов и задач

##### 5. RedisLock (lock.py)
Реализация распределенной блокировки:
- Асинхронное получение и освобождение блокировок
- Поддержка продления времени жизни блокировки
- Контекстный менеджер для автоматического управления блокировками

#### Архитектура Redis Module

```
+-------------------+
|   RedisManager    |  - Управление пулом подключений и клиентом
+-------------------+
          |
          v
+-------------------+     +------------------+
|   RedisService    |<--->|     RedisKeys    |  - Генерация ключей
+-------------------+     +------------------+
          |
          v
+-------------------+
|    LockService    |  - Фабрика блокировок
+-------------------+
          |
          v
+-------------------+
|     RedisLock     |  - Реализация распределенной блокировки
+-------------------+
```

### Docker и развертывание

#### Dockerfile
- Использует образ python:3.13-slim
- Устанавливает зависимости через uv
- Копирует исходный код
- Запускает приложение через `uv run python src/main.py`

#### docker-compose.yaml
- Сервис `bot` - основное приложение
- Сервис `cache` - Redis сервер
- Настроен healthcheck для Redis
- Монтируются session-файлы для сохранения авторизации

#### Конфигурация
- Поддержка локального режима (через .env файлы)
- Поддержка production режима (через Docker Secrets)
- Валидация параметров конфигурации
- Маскировка секретов в логах

## Безопасность

- Session-файлы не попадают в Git (.gitignore)
- .env файлы не коммитятся
- Использование Docker Secrets в production
- Валидация конфигурации
- Маскировка секретов в логах

## Обработка ошибок

- Централизованная обработка исключений в MainBot
- Логирование ошибок через loguru
- Graceful shutdown для всех компонентов
- Проверка состояния подключения к Redis
- Обработка ошибок парсинга каналов

## Масштабируемость

- Распределенные блокировки для работы в многопоточной среде
- Единый пул подключений к Redis
- Сериализация операций через FSM
- Поддержка нескольких одновременных пользователей
